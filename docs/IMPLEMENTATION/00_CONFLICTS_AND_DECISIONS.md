## Gaps requiring a decision before production

1. Define browser token storage/CSRF policy and an authenticated streaming path. WEB_FLOW records these as API/security gaps.
2. Resolve the 27 WEB_FLOW gaps before enabling the affected controls, especially alert filters/actions, site-scoped GIS, watchlist writes, zone version/rollback, model upload/rollback, notification preferences, and sync conflict operations.
3. Confirm actual camera/NVR/VMS models, ONVIF profiles, stream codecs, RTSP network policy, and a safe test site.
4. Approve datasets, annotation terms, model licenses, face-data legal basis, retention/legal hold, and who can enroll/search biometric records.
5. Confirm whether a GPU/Jetson/Intel NUC, IR/thermal cameras, siren relay, and offline tile pack are available; provide named hardware and safe test procedures.
6. Confirm C2/C4I interfaces, security requirements, payload owners, TLS/certificate policy, and whether a mock-only demo is acceptable.
7. Confirm event retention across Timescale chunks, grants/roles, backup/restore, key management, and SQL execution against a clean PostgreSQL 16/TimescaleDB instance.
8. Use TRD numeric defaults as defaults (capture 12 FPS target, detector 640/1280 input, ByteTrack confirmation 3 frames, alert cooldown 30 seconds, evidence 10 seconds pre/post, JWT 15 minutes). Measure/reconfigure only with an approved contract change.

No unresolved gap is presented as an implemented feature. Task owners may not relax these controls without an approved PRD/TRD decision.
