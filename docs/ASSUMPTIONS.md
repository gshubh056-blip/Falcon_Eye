# Backend Assumptions and Resolutions

| ID | Assumption / resolution | Reason / validation |
|---|---|---|
| BA-01 | Follow TRD Python 3.12.9, React 18, PostgreSQL 16/TimescaleDB, and repository path `apps/`; do not adopt Python 3.11 from the later prompt. | TRD is the repository's technical authority. Current local Python is 3.14.6 and is not the pinned test environment. |
| BA-02 | Preserve PRD table names (`sites`, `cameras`, `zones`, `users`, `roles`, `events`, `detections`, `tracks`, `alerts`, `alert_actions`, `watchlist_plates`, `watchlist_faces`, `face_embeddings`, `evidence_files`, `ledger_entries`, `audit_logs`, `models`, `configs`, `devices`, `health_metrics`, `sync_queue`). | TRD Section 9 names these exact contracts. Extra support tables may be added. |
| BA-03 | Use PRD severity `info`, `low`, `medium`, `high`, `critical` and alert states `new`, `acknowledged`, `escalated`, `resolved`, `false_positive`, `closed`. | Conflicting enums in the new prompt are not substituted into existing API/database contracts. |
| BA-04 | Use `devices` as the edge-node table; a device row represents an edge node/site device. | TRD names `devices`; avoid two sources of node identity. |
| BA-05 | Add `organizations` as a single-tenant-ready parent for sites, but use one organization in the MVP. | The prompt requests organizations; PRD site model does not specify multi-tenancy. |
| BA-06 | Store camera secrets by `credential_ref`; the schema does not store raw RTSP/ONVIF passwords. | PRD FR-003 and SEC-004. Secret backend/vault integration is outside SQL DDL. |
| BA-07 | Use UUIDv4 generated by PostgreSQL `gen_random_uuid()` for database IDs; use explicit sequence and idempotency key for sync ordering. | TRD contract; UUIDv7 extension not guaranteed in offline PostgreSQL image. |
| BA-08 | Time-series hypertables use composite keys containing their partition timestamp and child rows carry the timestamp for composite references. | TimescaleDB uniqueness/foreign-key requirements and PRD DB-001. |
| BA-09 | Keep face embeddings encrypted at rest as opaque bytes with a key reference; FAISS index is rebuildable and not the source of truth. | Privacy and resilience; key management is deployment-side. |
| BA-10 | FRS/ANPR are disabled unless legal basis, expiry, authorization, purpose logging and human-review workflows are configured. | PRD FR-024–026, NG-02–04 and privacy register. |
| BA-11 | No default administrator credentials are included. Initial admin must be created by a secured bootstrap process. | Avoid committing shared or guessable credentials. |
| BA-12 | External anchoring, action recognition, cross-camera re-identification and model hot-swap are optional phases; schema hooks do not indicate they are implemented. | PRD priority and quality rules. |
| BA-13 | The SQL file is a baseline bootstrap schema for PostgreSQL 16 plus the matching TimescaleDB extension. It is not a substitute for reviewed Alembic migrations. | No database server, Docker, or PostgreSQL client is installed in this workspace. |
| BA-14 | The later prompt's 30 FPS Jetson goal, 97% benchmark reference and sub-100 ms ANPR target are measurement targets only, not guaranteed behavior or schema constraints. | TRD/PRD performance targets are measured on specific hardware/data; no FALCON benchmark has been run. |
